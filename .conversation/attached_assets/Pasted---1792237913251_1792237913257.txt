# خطة التنفيذ الفعلية: منصة الرياضة والصحة الشخصية

سنحوّل فكرتك إلى مشروع برمجي قابل للبناء بميزانية صفر درهم، باستخدام البرمجة والأدوات المجانية، مع دعم العربية والإنجليزية من البداية.

سأتعامل مع المشروع باعتباره منتجًا تريد تطويره إلى شركة مستقبلًا، ولذلك سنبني أساسًا يمكن توسيعه دون إعادة كتابة كل شيء.

القرار التقني الأساسي: ابدأ بتطبيق ويب متجاوب يعمل على الهاتف والحاسوب، مع محرك توصيات يعتمد على قواعد واضحة، ثم أضف الحسابات وقاعدة البيانات والمساعد الذكي تدريجيًا. لا تحتاج إلى تدريب نموذج ذكاء اصطناعي خاص بك.

## 3. صفحات النسخة الأولى ومساراتها

سنستخدم مسارات واضحة، مع الاحتفاظ باللغة المختارة للمستخدم.

| الصفحة         | المسار المقترح  | الوظيفة                                |
| -------------- | --------------- | -------------------------------------- |
| الرئيسية       | `/`             | تعريف المنصة وبدء الاستخدام            |
| الاستبيان      | `/onboarding`   | جمع المعلومات الضرورية                 |
| معاينة الخطة   | `/plan-preview` | عرض الخطة المقترحة وسبب اختيارها       |
| لوحة المتابعة  | `/dashboard`    | النشاط والأهداف والتقدم                |
| البرنامج       | `/plan`         | تفاصيل الجلسات والتمارين               |
| مكتبة التمارين | `/exercises`    | البحث والتصفية والتفاصيل               |
| العادات الصحية | `/wellness`     | محتوى النوم والتغذية والترطيب والتعافي |
| المساعد        | `/assistant`    | الإجابات العامة المستندة إلى المصادر   |
| الملف الشخصي   | `/profile`      | إعدادات الحساب والبيانات               |
| الخصوصية       | `/privacy`      | شرح البيانات وحقوق المستخدم            |

في النسخة الأولية، يمكن تنفيذ هذه المسارات باستخدام موجّه بسيط للصفحات بدل إضافة مكتبة توجيه مستقلة. لا تحتاج إلى إطار عمل إضافي لمجرد وجود عدة صفحات.

### تجربة المستخدم الأساسية

1\. الصفحة الرئيسية

يتعرف المستخدم على الخدمة

2\. الاستبيان

يجيب عن أسئلة الهدف والوقت والمعدات

3\. بوابة السلامة

يتحقق النظام من ملاءمة التخصيص

4\. معاينة الخطة

يعرض برنامجًا مراجعًا وسبب اختياره

5\. التنفيذ والمتابعة

يسجل المستخدم الجلسات ويعود لمراجعة تقدمه

يجب ألا يُطلب من المستخدم تقديم معلومات صحية حساسة لمجرد تصفح الموسوعة. اجمع ما تحتاج إليه فقط عند بدء التخصيص، واشرح الغرض منه قبل جمعه.

## 4. دعم العربية والإنجليزية من البداية

أنصحك باستخدام ملفات ترجمة منفصلة، بدل كتابة النصوص مباشرة داخل كل صفحة.

مثال `src/i18n/ar.js`:

```

export default {
  appName: "لياقتي",
  home: "الرئيسية",
  start: "ابدأ رحلتك",
  dashboard: "لوحة المتابعة",
  exercises: "التمارين",
  wellness: "العادات الصحية",
  next: "التالي",
  back: "رجوع",
  save: "حفظ",
  loading: "جارٍ التحميل..."
};

```

ومثال `src/i18n/en.js`:

```

export default {
  appName: "FitWell",
  home: "Home",
  start: "Start your journey",
  dashboard: "Dashboard",
  exercises: "Exercises",
  wellness: "Healthy habits",
  next: "Next",
  back: "Back",
  save: "Save",
  loading: "Loading..."
};

```

بعدها أنشئ `src/i18n/index.js`:

```

import ar from "./ar.js";
import en from "./en.js";

const dictionaries = { ar, en };

export function translate(key, language = "ar") {
  return dictionaries[language]?.[key]
    ?? dictionaries.ar[key]
    ?? key;
}

export function setDocumentLanguage(language) {
  document.documentElement.lang = language;
  document.documentElement.dir =
    language === "ar" ? "rtl" : "ltr";
}

```

هذه بداية بسيطة. عند ربط اللغة بالواجهة، حدّث الاتجاه `dir` عند تغيير اللغة، واجعل إعداد اللغة محفوظًا وفق اختيار المستخدم. تأكد أيضًا من أن الأرقام والتواريخ وأسماء التمارين تظهر بشكل مناسب في اللغتين.

لا تترجم الواجهة فقط؛ بل اجعل عناوين التمارين والمقالات وتعليماتها ومصادرها قابلة للتوطين أيضًا.

## 5. تصميم قاعدة البيانات

سنستخدم PostgreSQL عبر Supabase عندما تصبح النسخة المحلية جاهزة. لكن ينبغي تصميم الجداول بما يضمن أن كل مستخدم لا يرى إلا بياناته.

### الجداول الأساسية

profiles

اللغة المفضلة، الهدف العام، إعدادات الحساب.

onboarding_answers

إجابات الاستبيان الضرورية لتخصيص البرامج.

exercises

بيانات التمارين والتعليمات والمعدات وروابط الفيديو.

programs

البرامج المراجعة والأهداف والمستويات.

program_exercises

التمارين المرتبطة بكل برنامج وترتيبها.

user_programs

البرنامج المخصص للمستخدم وإصداره وتاريخ بدايته.

workout_logs

الجلسات المكتملة والتاريخ وتقييم الصعوبة.

wellness_articles

المقالات الصحية والمصادر واللغات وتواريخ المراجعة.

habit_logs

سجل العادات التي اختار المستخدم تتبعها.

### مخطط SQL أولي

أنشئ ملف `supabase/migrations/001_initial_schema.sql` واستخدمه كأساس. هذا المخطط يركز على الحسابات والبرامج والتقدم، ويمكن توسيعه بعد اختبار المنتج.

```

create extension if not exists pgcrypto;

create table public.profiles (
  id uuid primary key references auth.users(id)
    on delete cascade,
  language text not null default 'ar'
    check (language in ('ar', 'en')),
  created_at timestamptz not null default now()
);

create table public.exercises (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,
  title_ar text not null,
  title_en text not null,
  level text not null
    check (level in ('beginner', 'intermediate', 'advanced')),
  equipment text[] not null default '{}',
  instructions_ar text not null,
  instructions_en text not null,
  video_url text,
  reviewed_at date,
  is_published boolean not null default false
);

create table public.programs (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,
  title_ar text not null,
  title_en text not null,
  goal text not null,
  level text not null default 'beginner',
  days_per_week integer not null
    check (days_per_week between 1 and 7),
  reviewed_at date,
  is_published boolean not null default false
);

create table public.user_programs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id)
    on delete cascade,
  program_id uuid not null references public.programs(id),
  started_at date not null default current_date,
  created_at timestamptz not null default now()
);

create table public.workout_logs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id)
    on delete cascade,
  user_program_id uuid references public.user_programs(id)
    on delete set null,
  completed_at timestamptz not null default now(),
  difficulty smallint check (difficulty between 1 and 5),
  notes text
);

alter table public.profiles enable row level security;
alter table public.user_programs enable row level security;
alter table public.workout_logs enable row level security;

create policy "Read own profile"
on public.profiles for select
using ((select auth.uid()) = id);

create policy "Insert own profile"
on public.profiles for insert
with check ((select auth.uid()) = id);

create policy "Update own profile"
on public.profiles for update
using ((select auth.uid()) = id)
with check ((select auth.uid()) = id);

create policy "Read own programs"
on public.user_programs for select
using ((select auth.uid()) = user_id);

create policy "Insert own programs"
on public.user_programs for insert
with check ((select auth.uid()) = user_id);

create policy "Read own workout logs"
on public.workout_logs for select
using ((select auth.uid()) = user_id);

create policy "Insert own workout logs"
on public.workout_logs for insert
with check ((select auth.uid()) = user_id);

```

هذا مخطط أولي وليس قاعدة بيانات جاهزة للإطلاق. قبل الاستخدام الحقيقي، يجب إضافة سياسات التعديل والحذف اللازمة، والتحقق من كل الجداول الجديدة، وتحديد صلاحيات القراءة العامة للمحتوى المنشور. ويجب أن تتضمن الجداول التي يملكها المستخدم سياسات مناسبة على جميع العمليات التي تسمح بها الواجهة.

كذلك لا يكفي أن يكون `user_id` مساويًا للمستخدم الحالي: يجب التحقق من أن `program_id` يشير إلى برنامج منشور ومسموح به، وأن `user_program_id` في سجل النشاط يعود إلى المستخدم نفسه. استخدم قيودًا أو إجراءات خادمية مناسبة لمنع ربط السجلات ببيانات مستخدم آخر.

مهم: لا تضع مفتاح `service_role` الخاص بـ Supabase داخل الواجهة أو مستودع GitHub. استخدم المفتاح العام المخصص للعميل فقط مع سياسات RLS صحيحة، واحتفظ بأي أسرار خادمية في متغيرات بيئة آمنة.

## 6. خطوات التنفيذ الأولى على حاسوبك

سنبدأ بإنشاء واجهة تعمل محليًا قبل ربط قاعدة البيانات. بهذه الطريقة يمكنك اختبار التصميم والتوصيات دون جمع أي بيانات حقيقية.

### الخطوة الأولى: تثبيت الأدوات

تحتاج إلى:

- Node.js بإصدار LTS مدعوم.
- Visual Studio Code.
- Git.

تحقق من التثبيت بفتح الطرفية وكتابة:

```

node --version
npm --version
git --version

```

إذا ظهرت أرقام الإصدارات، فأنت جاهز للبدء.

### الخطوة الثانية: إنشاء المشروع

نفّذ الأوامر التالية:

```

npm create vite@latest fitwell-platform -- --template vanilla
cd fitwell-platform
npm install
npm run dev

```

سيفتح Vite خادم تطوير محليًا ويعرض لك رابطًا محليًا، عادةً `http://localhost:5173`. افتحه في المتصفح لترى المشروع الأساسي.

بعد ذلك أنشئ مستودع Git:

```

git init
git add .
git commit -m "Initial Vite project"

```

## 7. بناء محرك التوصيات قبل الذكاء الاصطناعي

أنصحك أن تجعل أول نسخة من `recommendationService.js` تعتمد على قواعد واضحة وبيانات تجريبية.

في `src/data/programs.js`، يمكنك البدء ببرامج وصفية محدودة:

```

export const programs = [
  {
    id: "beginner-home-general",
    goals: ["general", "fitness"],
    level: "beginner",
    location: "home",
    equipment: ["none"],
    daysPerWeek: [2, 3],
    reviewed: false
  }
];

```

لاحظ أن `reviewed: false` تعني أن هذا سجل تجريبي، وليس برنامجًا جاهزًا للتوصية به. يجب ألا يظهر في النتائج الفعلية حتى تتم مراجعة محتواه التدريبي والصحي.

بعد إعداد البيانات المراجعة، يمكن لخدمة التوصيات تصفية البرامج:

```

export function findMatchingPrograms(profile, programs) {
  if (!profile || !Array.isArray(programs)) {
    return [];
  }

  // لا تنشئ برنامجًا عند وجود قيد يستلزم التقييم.
  if (profile.safetyStatus !== "cleared") {
    return [];
  }

  return programs.filter((program) => {
    return (
      program.reviewed === true &&
      program.goals.includes(profile.goal) &&
      program.level === profile.level &&
      program.location === profile.location &&
      program.equipment.includes(profile.equipment) &&
      program.daysPerWeek.includes(profile.daysPerWeek)
    );
  });
}

```

هذا مثال تعليمي مبسط. في التطبيق الحقيقي، لا يكفي حقل `safetyStatus` يرسله المتصفح؛ يجب أن يفرض الخادم قواعد السلامة، وأن يتحقق من البيانات ومن النسخة المراجعة للبرنامج. كما أن المطابقة التامة قد لا تجد برنامجًا، لذا يمكن لاحقًا إضافة قواعد بدائل آمنة ومراجعة، دون تجاوز أي قيد صحي.

### ما الذي نختبره هنا؟

- هل يحصل المستخدم على البرامج التي تطابق اختياراته؟
- هل يتم استبعاد البرامج غير المراجعة؟
- هل يتعامل النظام مع الإجابات الناقصة بصورة صحيحة؟
- هل يتوقف التخصيص عند وجود قيد يحتاج إلى تقييم؟
- هل يوضح النظام سبب عدم العثور على برنامج مناسب؟

لا تربط خدمة الذكاء الاصطناعي بهذه المرحلة بعد. أولًا تأكد من أن قواعد الاختيار تعمل ويمكن تفسير نتائجها واختبارها.

## 8. حماية البيانات والسلامة الصحية

هذه متطلبات أساسية في التصميم، وليست ميزات إضافية نؤجلها إلى آخر المشروع.

تقليل البيانات

لا تجمع تشخيصات أو تفاصيل أدوية أو قياسات صحية دقيقة إلا إذا كانت ضرورية فعلًا لوظيفة محددة. ولا تستخدم بيانات حقيقية في اختباراتك الأولى.

التحكم في الوصول

فعّل RLS في Supabase لكل جدول خاص بالمستخدمين. اختبر القراءة والتعديل والحذف بحسابين مختلفين، وتأكد أن كل مستخدم لا يصل إلا إلى سجلاته.

بوابة السلامة

يجب أن تميز المنصة بين التثقيف الرياضي العام وبين الحالات التي تتطلب تقييمًا مختصًا. لا تسمح للمساعد أو لمحرك الخطط بتجاوز قيود السلامة.

مصادر المحتوى

احتفظ بمصدر كل مقالة أو تمرين، وتاريخ المراجعة، واسم أو صفة المراجع عند الاقتضاء. لا تستخدم فيديوهات الآخرين دون التحقق من حقوق استخدامها.

قبل إطلاق المنصة للجمهور في المغرب، راجع المتطلبات القانونية ذات الصلة بحماية البيانات الشخصية، بما فيها القانون 09-08، والتزامات المعالجة والنقل إلى الخارج عند انطباقها، مع مختص قانوني عند الحاجة. لا تعتبر الخطة المجانية لخدمة استضافة ضمانًا للامتثال القانوني.

## 9. خطة العمل العملية للأيام الأربعة عشر الأولى

هذه خطة بداية قابلة للتعديل بحسب وقتك وخبرتك. الهدف في نهاية الأسبوعين هو نموذج أولي يعمل محليًا، وليس منتجًا طبيًا أو تجاريًا مكتملًا.
